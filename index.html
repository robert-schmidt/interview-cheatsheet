OOP Four pillars

  • Encapsulation: hide state behind behavior; invariants enforced in one place.
  • Abstraction: expose what, hide how (interfaces, public API).
  • Inheritance: "is-a" reuse. Deep trees = fragile base class.
  • Polymorphism: one interface, many forms. Subtype (override), parametric (generics), ad-hoc (overload).
  • Senior signal: say where each one bites you, not just the definition.

OOP Composition over inheritance

// inheritance: behavior locked in at compile time
class LoggingRepo extends SqlRepo { ... }
// composition: behavior injected, swappable, testable
class OrderService {
  constructor(private repo: Repo, private log: Logger) {}
  place(o: Order) { this.repo.save(o); this.log.info("placed", o.id); }
}
  • Prefer has-a + interfaces; inherit only for true is-a that honors Liskov.
  • Composition enables Strategy, Decorator and DI naturally.

KEY DIP vs DI vs IoC container

  • DIP = the principle (depend on abstractions).
  • DI = the technique (pass deps in, usually via constructor).
  • Container = the tool (Spring, .NET DI, Guice, NestJS resolve them).
  • Anti-pattern: Service Locator (Container.get(X) inside business code) hides deps and breaks tests.
  • Separating these three cleanly is a senior signal.

OOP Coupling, cohesion, Demeter

  • Low coupling between modules, high cohesion within them.
  • Law of Demeter: talk to friends only. No a.getB().getC().do() train wrecks.
  • Tell, don't ask: account.withdraw(x), not if (acc.balance > x) acc.balance -= x.
  • Anemic domain model: data bags + logic in services. OK for CRUD, smell for rich domains.

SOLID The five

  • Single Responsibility: one reason to change (one actor). Invoice ≠ InvoicePrinter ≠ InvoiceRepo.
  • Open/Closed: add behavior by adding code (new Strategy/plugin), not editing tested code.
  • Liskov: subtypes must honor the contract. Classic break: Square extends Rectangle (setWidth changes height).
  • Interface Segregation: many small interfaces > one fat one. No Printer.fax() throwing NotSupported.
  • Dependency Inversion: high-level policy and low-level details both depend on abstractions.

SOLID OCP in 8 lines

# closed: every new type edits this function
def price(kind, base):
    if kind == "vip": return base * 0.8
    if kind == "sale": return base * 0.5
# open: new behavior = new class, zero edits
class Discount(Protocol):
    def apply(self, base: float) -> float: ...
def price(d: Discount, base): return d.apply(base)

GoF Creational

  • Factory Method: subclass/function decides which concrete to create.
  • Abstract Factory: families of related objects (UI kit per OS, driver per cloud).
  • Builder: step-by-step construction of complex/immutable objects; fluent API.
  • Prototype: clone an existing instance.
  • Singleton: one instance. Often an anti-pattern (global state, hidden deps). Prefer a DI-scoped singleton.

GoF Structural

  • Adapter: convert one interface to another (wrap a 3rd-party SDK).
  • Decorator: wrap to add behavior, same interface (caching, logging, retry).
  • Facade: simple front for a complex subsystem.
  • Proxy: same interface, controls access (lazy load, remote, auth).
  • Composite: tree where leaf and group share an interface (UI, file system).
  • Bridge: split abstraction from implementation so both vary.
  • Flyweight: share immutable intrinsic state (glyphs, tiles).

GoF Behavioral

  • Strategy: swap algorithms behind an interface (payment, pricing, routing).
  • Observer: subscribers notified on change (events, reactive UIs).
  • Command: request as an object → queue, undo, audit log.
  • State: behavior changes with internal state (order lifecycle FSM).
  • Template Method: base defines skeleton, subclasses fill steps.
  • Chain of Responsibility: pass along handlers (HTTP middleware).
  • Iterator · Visitor · Mediator · Memento: traverse · add ops to a tree · centralize comms · snapshot state.

ARCH CQRS & Event Sourcing

  • CQRS: separate write model (commands, validation) from read models (denormalized, fast queries).
  • Event Sourcing: store events, not current state. State = fold(events).
  • Gains: full audit log, time travel, rebuild new projections by replay.
  • Costs: eventual consistency of reads, event schema versioning, snapshots needed for long streams.
  • Use them independently; neither requires the other.

EDA Event-driven basics

  • Event = fact, past tense, many listeners (PaymentCaptured). Command = intent, one handler (CapturePayment).
  • Queue (point-to-point): each message to one consumer; work distribution.
  • Pub/Sub / topic: each subscriber gets a copy; fan-out.
  • Choreography: services react to each other's events (loose, harder to trace).
  • Orchestration: a coordinator tells services what to do (explicit, central).
  • Event types: notification (thin, "go fetch") vs event-carried state transfer (fat payload).

EDA Delivery guarantees

  • At-most-once (may lose) · At-least-once (may duplicate) · Exactly-once ≈ at-least-once + idempotent consumer.
  • Idempotency key: store processed IDs; dedupe on retry. No double charges.
  • Ordering only within a partition/key: route by orderId.
  • Retries: exponential backoff + jitter, capped; then DLQ.
  • Poison message: always fails → blocks partition unless moved to DLQ.
def handle(msg):
    if store.seen(msg.id): return          # idempotent
    with tx: apply(msg); store.mark(msg.id)

EDA Outbox, CDC, Saga

  • Dual-write problem: save to DB and publish to broker. One can fail.
  • Transactional Outbox: write event to an outbox table in the same txn; relay publishes it.
  • CDC: tail the DB log (Debezium) → stream changes as events.
  • Inbox: consumer-side dedupe table.
  • Saga: long-running distributed txn = local txns + compensating actions (refund, release stock). No 2PC.

STREAM Stream processing

  • Batch (bounded, high latency) vs stream (unbounded, low latency).
  • Windows: tumbling (fixed, no overlap) · sliding (overlap) · session (gap-based).
  • Event time vs processing time; watermarks handle late data.
  • Backpressure: slow consumer signals producer to slow down.
  • Lambda (batch + speed layers) vs Kappa (stream only, replay the log).
  • Tools: Flink, Kafka Streams, Spark Structured Streaming, Beam.

CLOUD HA & Disaster Recovery

  • RTO = how long to recover. RPO = how much data you can lose.
  • DR tiers: backup/restore → pilot light → warm standby → active-active (cost ↑, RTO ↓).
  • Availability math: 99.9% ≈ 8.8 h/yr · 99.99% ≈ 53 min/yr. Serial deps multiply (0.99×0.99 = 0.98).
  • No single points of failure; health checks + automatic failover.
  • Chaos engineering: inject failure deliberately to prove resilience.
  • FinOps: spot/preemptible, reserved/savings plans, right-size, watch egress costs, tag everything.

SD Scaling & load balancing

  • Vertical (bigger box, simple, ceiling) vs horizontal (more boxes, needs stateless services).
  • L4 LB (TCP, fast, blind) vs L7 LB (HTTP-aware: path routing, headers, TLS termination).
  • Algorithms: round robin · weighted · least connections · IP hash · consistent hashing.
  • Sticky sessions = scaling smell; move session to Redis/JWT.
  • Autoscaling on CPU, queue depth or custom metrics; scale-in carefully.

SD Replication & sharding

  • Leader-follower: writes to leader, reads scale on replicas → replication lag.
  • Multi-leader: multi-region writes → conflict resolution (LWW, CRDTs).
  • Leaderless (Dynamo/Cassandra): quorum W + R > N.
  • Sharding: range (scans, hotspots) · hash (even, no ranges) · directory (flexible).
  • Consistent hashing: ring + virtual nodes → adding a node moves ~1/N keys.
  • Hot partitions (celebrity user) → key salting, split hot keys.

  • Token bucket: refill at rate r, burst up to capacity. Most common.
  • Leaky bucket: smooth constant outflow.

def lower_bound(a, x):            # first i with a[i] >= x
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x: lo = mid + 1
        else: hi = mid
    return lo

def longest_unique(s):            # sliding window
    seen, l, best = {}, 0, 0
    for r, ch in enumerate(s):
        if seen.get(ch, -1) >= l: l = seen[ch] + 1
        seen[ch] = r; best = max(best, r - l + 1)
    return best

CONC Concurrency core

  • Concurrency = dealing with many things (structure). Parallelism = doing many at once (execution).
  • Process (own memory) · thread (shared memory) · coroutine / green thread (user-space, cheap).
  • Race condition: result depends on timing. Fix: mutex, atomics, immutability, confinement.
  • Deadlock needs all 4 (Coffman): mutual exclusion, hold-and-wait, no preemption, circular wait. Break one (lock ordering).
  • Livelock (busy, no progress) · starvation (never scheduled).
  • Primitives: mutex · RW lock · semaphore · condition variable · CAS (lock-free) · barriers.
  • Visibility: without a memory barrier/volatile/atomic, other threads may see stale values.

CONC Models & patterns

  • Event loop + non-blocking I/O (Node, asyncio, Netty): great for I/O-bound; never block the loop.
  • Actors (Erlang, Akka, Orleans): private state, communicate by messages.
  • CSP (Go): processes + channels.
  • Futures / promises: placeholder for a later value.
  • Producer-consumer with a bounded queue = built-in backpressure.
  • Thread pool: bound concurrency; size ≈ cores (CPU) or higher (I/O).
  • Structured concurrency: child tasks can't outlive parent scope (Kotlin, Java 21+, Trio).

DL Deep learning

  • Neural net = layers of weighted sums + non-linear activations (ReLU, GELU; softmax → probabilities).
  • Loss (cross-entropy, MSE) → backprop computes gradients → optimizer (SGD, Adam) updates weights.
  • Learning rate: the most important hyperparameter. Warmup + decay schedules.
  • Epoch = one pass over data; batch = examples per update.
  • Architectures: CNN (images) · RNN/LSTM (sequences, legacy) · Transformer (everything now).
  • Stability: normalization (LayerNorm), residual connections, gradient clipping.

LLM How LLMs work

  • Tokens: subword pieces (BPE). ~4 chars ≈ 1 token in English. Pricing and limits are per token.
  • Embeddings: tokens → vectors where meaning ≈ direction.
  • Self-attention: every token weighs every other token (Q·K → weights over V). Cost O(n²) in length.
  • Decoder-only Transformer, trained on next-token prediction (pretraining), then post-trained to follow instructions.
  • Context window: max tokens in + out per call (the model's working memory).
  • Inference: autoregressive, one token at a time; KV cache avoids recomputing past tokens.
  • Scaling laws: loss falls predictably with more params, data, compute.
